# Building pages from data

The `/app` templates turn **what a page needs to do** plus **a sample API response or schema**
into a working page: `DataTablePage` for many records, `DetailsPage` for one record,
`DashboardPage` for numbers over time, all inside one `AppShell`.

```ts
import { DataTablePage, DetailsPage, DashboardPage } from '@true-tech-team/ui-components/app';
```

The guidance below is rendered from `guidelines/app/` (the same files ship in the npm package
under `guidelines/app/`), so it never drifts from what coding agents read. Rule IDs (`APP-*`,
`FIELD-*`, `HIER-*`, `APP-STATE-*`, `APP-PLUMB-*`) are meant to be cited in briefs, code comments
and PRs.

## See the templates

<Markdown options={guideOptions}>{`
| Template                                                               | Use for                                                                       |

| [AppShell](?path=/docs/app-builder-templates-appshell--docs)           | The app frame, once per app: Navbar, sidebar, skip link, mobile navigation    |
| [DataTablePage](?path=/docs/app-builder-templates-datatablepage--docs) | Many records: search, filters, sort, pagination, views, row actions, detail   |
| [DetailsPage](?path=/docs/app-builder-templates-detailspage--docs)     | One record: key facts, URL-bound tabs, main and side columns                  |
| [DashboardPage](?path=/docs/app-builder-templates-dashboardpage--docs) | KPIs, charts and activity over a URL-bound time range                         |
| [PageHeader](?path=/docs/app-builder-templates-pageheader--docs)       | Title, status, breadcrumbs, actions and tabs on a custom page                 |
| [Blocks](?path=/docs/app-builder-templates-blocks--docs)               | PropertyList, KeyFacts, ActivityTimeline, Notes, MediaGallery, RelatedRecords |
| [FieldValue](?path=/docs/app-builder-templates-fieldvalue--docs)       | One value rendered by \`FieldKind\`, the same everywhere                        |
`}</Markdown>
